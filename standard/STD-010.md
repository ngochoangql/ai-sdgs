# STD-010 — AI AGENT ROLES, PERMISSIONS & MULTI-AGENT COORDINATION

## 1. PURPOSE & GOVERNANCE SCOPE

`STD-010` enforces Least Privilege execution boundaries, file/directory access scopes, command execution guardrails, and concurrency coordination protocols across single-agent coding assistants and multi-agent / subagent swarms operating on a shared codebase.

---

## 2. TERMS & NORMATIVE DEFINITIONS

- **Write Lease (Scope Lock):** Exclusive temporary assignment of a specific set of files or module globs to a single active AI agent/task (`CR-XXXX` or subagent ID) to prevent concurrent semantic collisions.
- **Destructive Command:** Any shell or VCS operation capable of irreversible state loss or history rewriting (`git reset --hard`, `git push --force`, `rm -rf` outside build caches, dropping non-ephemeral databases, mutating remote cloud state).

---

## 3. ROLES & AUTHORITY BOUNDARIES

- **`HUM-OWNER` / `HUM-SEC`:** Define `protected_paths`, command execution boundaries, and adapter sandbox configurations in `.aisdgs/config.yaml`.
- **`AI-ANALYST` (`Read + Draft Governance`):** Permitted to read authorized repository files and write `DRAFT`/`ANALYZED` proposals in `changes/records/` or `DRAFT` specs; prohibited from mutating `src/`, tests, or `APPROVED` baselines.
- **`AI-IMPL` (`Scoped Read + Write Code/Tests`):** Permitted to modify only the source, test, and contract files authorized by the active task/`CR-*` lease.
- **`AI-VERIFY` (`Read + Execute Checks + Write Reports`):** Permitted to execute non-destructive build/test/audit commands and write `quality/reports/*`; Ideally separated from `AI-IMPL` in multi-agent `STRICT` workflows to prevent self-grading bias.
- **`AI-STEWARD` (`Sync + Audit Prep`):** Permitted to run `aisdgs adapter sync`, `aisdgs status`, and update `CHANGELOG-GOVERNANCE.md`.

---

## 4. NORMATIVE REQUIREMENTS

- **`STD-010-R01` `[NON-WAIVABLE]` — Least-Privilege Scoped Execution:** Every AI task or subagent invocation MUST operate with an explicit file-scope boundary (`allowed_write_globs` derived from the task or `CR-*` `affected_files`). An AI agent MUST NOT opportunistically edit, reformat, or refactor files outside its assigned task scope.
- **`STD-010-R02` `[NON-WAIVABLE]` — Protected Path Access Control:** `.aisdgs/config.yaml` MUST declare a `protected_paths` list including at minimum:
  1. `.aisdgs/**` (standard snapshot, lockfile, schemas, policies, config)
  2. `governance/**` (`PROJECT-CONSTITUTION.md`, `PROJECT-BASELINE.md`, `EXCEPTIONS.md`)
  3. `AGENTS.md` and generated vendor adapter files
  4. Package dependency manifests & lockfiles, database migration directories, and CI/CD pipeline definitions (`STD-008-R03`, `STD-008-R04`, `STD-012`).
  AI agents MUST NOT mutate any `protected_paths` match without explicit task/CR authorization covering that exact path.
- **`STD-010-R03` `[NON-WAIVABLE]` — Prohibition of Unconfirmed Destructive Commands:** AI agents MUST NOT execute destructive VCS, filesystem, or infrastructure commands (`git reset --hard`, `git checkout -- .` discarding user work, `git clean -fd`, `git push --force`, `git commit --no-verify`, production deployment/DB drop commands) without explicit, immediate human confirmation in the active session.
- **`STD-010-R04` `[WAIVABLE]` — Optional Role Topology (Zero Forced Swarm Overhead):** Projects MUST NOT be forced to deploy multiple concurrent AI agents. When a single AI coding session executes a workflow end-to-end, it MUST transition sequentially through logical profiles (`AI-ANALYST` → human gate if required → `AI-IMPL` → `AI-VERIFY`), honoring each profile's boundary at that step.
- **`STD-010-R05` `[WAIVABLE]` — Multi-Agent Exclusive Write Leases:** When two or more AI agents, background workers, or subagents operate concurrently on the same repository (whether in shared working tree or worktrees/branches targeting the same milestone):
  1. Each worker MUST receive a disjoint `allowed_write_globs` lease (or isolated branch tied to a distinct `CR-*`).
  2. Shared public contracts (`docs/contracts/**`, shared types/interfaces, DB schemas) MUST be frozen prior to parallel fan-out; workers MUST NOT mutate shared contracts mid-flight without coordinator escalation.
- **`STD-010-R06` `[WAIVABLE]` — Multi-Agent Conflict Arbitration:** If two parallel agents propose incompatible changes to a shared interface, requirement, or architectural pattern, neither agent MAY overwrite the other's work silently. The coordinator (or detecting agent) MUST halt merge, surface both proposals with trade-offs (`STD-006-R07`), and escalate to `HUM-ARCH` / `HUM-OWNER` (or an authorized `CR-*` update).
- **`STD-010-R07` `[WAIVABLE]` — Independent Verification Separation (`STRICT` Tier):** In `TIER-3: STRICT` workflows utilizing subagents, the `AI-VERIFY` / Reviewer profile evaluating `L3-Semantic-Audit` SHOULD run in a clean, independent agent context separate from the `AI-IMPL` context that authored the code, preventing confirmation bias.
- **`STD-010-R08` `[WAIVABLE]` — Adapter Sandbox Synchronization:** Whenever supported by the host AI coding tool (e.g., `.claude/settings.json` permissions, Cursor rules, MCP tool policies), `aisdgs adapter sync` SHOULD emit native read/write/command permission boundaries mirroring `.aisdgs/config.yaml` `protected_paths` (`Ring 1` defense under `DEC-007`).

## 5. OPERATIONAL PROCEDURES & WORKFLOWS

### 5.1 Single-Agent Sequential Profile Switching
1. **Start in `AI-ANALYST`:** Read `AGENTS.md`, classify prompt, inspect code, check `protected_paths`.
2. **Gate Check:** If Zero-CR authorized, switch to `AI-IMPL` with bounded file list; if CR required, draft `CR-XXXX` and pause for `HUM-*` approval.
3. **Execute in `AI-IMPL`:** Edit only authorized files; never touch unrelated modules.
4. **Switch to `AI-VERIFY`:** Run tests + `aisdgs validate`, report factual evidence (`STD-009-R01`).

### 5.2 Parallel Subagent / Swarm Coordination Protocol
1. **Freeze Shared Contracts First:** Approve interface/schema contracts in baseline or parent `CR-FULL` before spawning workers.
2. **Assign Disjoint Leases:** Coordinator passes explicit `allowed_write_globs` and read-only contract references in each subagent's prompt/brief.
3. **Verify Lease Containment Before Merge:** Run `aisdgs change verify` / `git diff --name-only` on each worker's output to verify zero out-of-lease file mutations before integrating.

## 7. EXCEPTIONS & ESCALATION RULES

- `STD-010-R01`, `STD-010-R02`, and `STD-010-R03` are **`[NON-WAIVABLE]`**.
- Repository-wide automated codemods (e.g., renaming a symbol across 200 files or formatting upgrade) are permitted ONLY when explicitly scoped as a dedicated `REFACTORING` or `TECHNICAL_CHANGE` `CR-*` approved by `HUM-OWNER` / `HUM-ARCH` (isolated from functional logic changes).

---

## 9. VERIFICATION CRITERIA & REQUIRED EVIDENCE

Compliance with `STD-010` is verified when:
1. `.aisdgs/config.yaml` defines non-empty `protected_paths` covering all four mandatory path groups (`STD-010-R02`).
2. `aisdgs validate` confirms zero unauthorized mutations on `protected_paths` and zero unarbitrated overlapping `IN_PROGRESS` CR file leases.
3. Generated tool adapters match `.aisdgs/config.yaml` boundaries with zero drift.
