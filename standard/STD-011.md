# STD-011 — PROMPT TRIAGE, PROGRESSIVE CONTEXT ROUTING & EVIDENCE REPORTING

## 1. PURPOSE & GOVERNANCE SCOPE

`STD-011` operationalizes how AI agents classify incoming natural-language prompts, manage finite LLM context windows via the 3-Tier Progressive Context Architecture, maintain vendor-neutral instruction synchronization, and report actions with anti-hallucination auditability.

---

## 2. TERMS & NORMATIVE DEFINITIONS

- **Context Router (`AGENTS.md`):** The compact (`≤ 150 lines`) root instruction file loaded at the start of every AI session containing project invariants, prompt triage routing, protected paths, and pointers to conditional Tier 1 playbooks.
- **Thin Vendor Bridge:** A minimal (`≤ 40 lines`) tool-specific entrypoint (`CLAUDE.md`, `GEMINI.md`, `.cursor/rules/aisdgs.mdc`) delegating normative governance authority to `AGENTS.md`.
- **Compound Prompt:** A single user message bundling multiple distinct intents (e.g., *"explain how billing works AND add Stripe webhook retry logic"*).

---

## 3. ROLES & AUTHORITY BOUNDARIES

- **`HUM-OWNER` / `HUM-ARCH`:** Approve `PROJECT-CONSTITUTION.md` and `.aisdgs/config.yaml` inputs from which `AGENTS.md` and vendor bridges are synchronized.
- **`AI-STEWARD`:** Runs `aisdgs adapter sync` to regenerate synchronized `AGENTS.md` and vendor bridges without manual drift.
- **All `AI-*` Profiles:** Must execute prompt triage prior to repository mutation, obey progressive context loading rules, and report factual claim states.

---

## 4. NORMATIVE REQUIREMENTS

- **`STD-011-R01` `[NON-WAIVABLE]` — Pre-Mutation Prompt Classification:** Before modifying any repository file or executing state-mutating commands, an AI agent MUST classify the user prompt into one or more of the nine canonical categories: `QUESTION` / `INFORMATION_REQUEST`, `GOVERNANCE_OR_DOC_SYNC`, `BUG_REPORT` / `BUG_FIX`, `REFACTORING`, `ENHANCEMENT`, `FEATURE_REQUEST`, `TECHNICAL_CHANGE`, `ARCHITECTURAL_CHANGE`, or `EMERGENCY_CHANGE`.
- **`STD-011-R02` `[NON-WAIVABLE]` — Highest-Risk Rule for Compound Prompts:** When a user submits a Compound Prompt combining multiple categories (e.g., `QUESTION` + `BUG_FIX` + `TECHNICAL_CHANGE`), the AI agent MAY answer read-only questions immediately, MUST decompose the mutating requests clearly, and MUST apply the governance gate of the **highest-risk category** before mutating files governed by that category.
- **`STD-011-R03` `[NON-WAIVABLE]` — Context Tier 0 Budget (`AGENTS.md ≤ 150 Lines`):** Every AI-SDGS repository MUST maintain a root `AGENTS.md` file strictly **at or below 150 lines** (`L2` enforced). `AGENTS.md` MUST contain ONLY:
  1. Project Identity, Adoption Tier, Onboarding Mode & Baseline State pointer.
  2. The Central Principle (`STD-001-R01`) & Non-Waivable Invariants summary.
  3. Compact 9-category Prompt Classification & Routing Table.
  4. Active `protected_paths` globs & `HUM-*` authority summary.
  5. Exact file pointers to `.aisdgs/policies/*.md` (Context Tier 1).
- **`STD-011-R04` `[WAIVABLE]` — Thin Vendor Adapter Delegation (`≤ 40 Lines`):** Any generated or maintained vendor-specific instruction file (`CLAUDE.md`, `GEMINI.md`, `.cursor/rules/aisdgs.mdc`, `.github/copilot-instructions.md`, `.kilocode/rules/*`) MUST remain **at or below 40 lines**, contain zero competing governance rule tables, and explicitly instruct the agent to read and obey root `AGENTS.md` as the Single Source of Truth (`STD-004-R01`).
- **`STD-011-R05` `[WAIVABLE]` — Conditional Context Tier 1 Playbook Loading:** Context Tier 1 operational policies (`.aisdgs/policies/*.md`, each **≤ 250 lines**) MUST NOT be copy-pasted inline into `AGENTS.md`; instead, AI agents MUST read the specific Tier 1 playbook(s) triggered by the prompt's classification (`prompt-and-change.md` for CRs, `architecture-and-contracts.md` for `ADR-*`/DB/API/dependencies, `verification-and-evidence.md` before task completion, `brownfield-and-emergency.md` for legacy/hotfix flows).
- **`STD-011-R06` `[NON-WAIVABLE]` — Factual Claim-State & Evidence Reporting:** In completion responses and governance records, AI agents MUST distinguish explicitly between `PROPOSED`, `APPROVED`, `IMPLEMENTED`, and `VERIFIED`, citing exact modified file paths, linked `CR-*`/`REQ-*`/`ADR-*` IDs (where applicable), and actual verification commands executed (`STD-009-R01`).
- **`STD-011-R07` `[WAIVABLE]` — Ambiguity Clarification Over Silent Assumption:** When a `FEATURE_REQUEST`, `TECHNICAL_CHANGE`, or `ARCHITECTURAL_CHANGE` contains material ambiguity affecting data schemas, security boundaries, public contracts, or external dependencies, the AI agent MUST surface concise clarifying questions or explicit `PROPOSED` options for human decision rather than silently hardcoding unapproved assumptions.
- **`STD-011-R08` `[WAIVABLE]` — Deterministic Adapter Drift Detection:** Modifying `.aisdgs/config.yaml` (`adoption_tier`, `protected_paths`, `adapters`) MUST be followed by `aisdgs adapter sync`. `aisdgs validate` MUST verify that `AGENTS.md` and enabled vendor bridges are synchronized and within line budgets.

## 5. OPERATIONAL PROCEDURES & WORKFLOWS

### 5.1 Standard AI Session Execution Loop
1. **Boot (`Tier 0`):** Agent loads `AGENTS.md` (directly or via `≤ 40` line vendor bridge).
2. **Triage:** Agent classifies incoming prompt (`R01`/`R02`).
   - If `QUESTION` / `INFORMATION_REQUEST`: inspect repo read-only and answer directly (zero Tier 1 overhead, zero CR overhead).
   - If mutating request: load matching Tier 1 policy file(s) from `.aisdgs/policies/` (`R05`).
3. **Authorize or Escalate:** Check `protected_paths` and tier routing (`STD-006-R01`). If human approval is required, output concise impact summary + `DRAFT`/`ANALYZED` `CR-XXXX` and wait.
4. **Execute & Verify:** Perform scoped edits, run tests + `aisdgs validate`, and output structured completion report (`R06`).

### 5.2 Synchronizing Multi-Tool Adapters (`aisdgs adapter sync`)
1. Read `.aisdgs/config.yaml` (`project`, `adoption_tier`, `onboarding_mode`, `protected_paths`, `adapters.targets`).
2. Render deterministic `AGENTS.md` (`≤ 150` lines) preserving project-configured protected paths and roles.
3. Render enabled thin bridges (`CLAUDE.md`, `GEMINI.md`, `.cursor/rules/aisdgs.mdc`, etc., each `≤ 40` lines) with synchronized checksum header/comment.

## 6. PROPORTIONAL TIER SCALING RULES

| Context & Reporting Rule | `TIER-1: LITE` | `TIER-2: STANDARD` | `TIER-3: STRICT` |
| :--- | :--- | :--- | :--- |
| `AGENTS.md ≤ 150` & Bridges `≤ 40` (`R03`, `R04`) | Mandatory (`MUST`) | Mandatory (`MUST`) | Mandatory (`MUST`) |
| Explicit Triage Declaration in Chat/CR | Implicit on `QUESTION`; explicit on `CR-*` | Explicit on mutating tasks & all `CR-*` | Explicit classification & scope header on every mutating response + audit log |
| Completion Evidence Format (`R06`) | Concise file + test summary | Structured CR `verification_evidence` + summary | Full CR evidence + `CHANGELOG-GOVERNANCE.md` + `L3` report link |

---

## 7. EXCEPTIONS & ESCALATION RULES

- `STD-011-R01`, `STD-011-R02`, `STD-011-R03`, and `STD-011-R06` are **`[NON-WAIVABLE]`**.
- If a project has unusually numerous `protected_paths` globs (> 40 custom globs) threatening the 150-line `AGENTS.md` ceiling, `AGENTS.md` MUST group them into top-level summary globs and point deterministically to `.aisdgs/config.yaml` rather than exceeding 150 lines.

---

## 9. VERIFICATION CRITERIA & REQUIRED EVIDENCE

Compliance with `STD-011` is verified when:
1. `AGENTS.md` exists, contains ≤ 150 lines, and passes required section/pointer checks.
2. Every enabled vendor adapter file contains ≤ 40 lines, references `AGENTS.md`, and passes sync verification (`aisdgs adapter sync --check` / `aisdgs validate`).
3. All `.aisdgs/policies/*.md` files contain ≤ 250 lines and match `standard-lock.yaml` digests.
